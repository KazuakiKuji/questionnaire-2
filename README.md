# ClaudeCode・AI活用 実態アンケート

社内 / 外部案件で分岐する Google フォームを作成し、回答を所属ごとに
スプレッドシートの「社内」「外部案件」タブへ振り分ける Apps Script プロジェクト。

スクリプトは **回答用スプレッドシートに紐づくコンテナバインドスクリプト**。
スプレッドシートは再生成せず、常に紐づいているものを更新する。
集まった回答は `buildAnalysis` で「分析」タブに集計し、前回アンケート（2026年4月）と比較できる。

## 構成

```text
.clasp.json          clasp 設定（scriptId / parentId=スプレッドシート / rootDir=src / push 順）
.claspignore         appsscript.json と *.js のみ push
package.json         clasp ラッパーの npm scripts
src/
  appsscript.json    マニフェスト（Asia/Tokyo, V8）
  constants.js       定数（名称・タブ名・選択肢・質問定義。JSDoc 付き）
  utils.js           共通関数（フォーム探索／生成、シート整形、回答先の再連携、トリガー）
  analysis.js        集計（buildAnalysis: 「分析」タブの作成。前回アンケートとの比較を含む）
  main.js            実行関数（createSurvey / onSubmit）
```

## セットアップ

```sh
npm install -g @google/clasp   # 未導入の場合
npm run login                  # clasp login
npm run push                   # src/ を Apps Script へ反映
npm run open                   # ブラウザでエディタを開く
```

他に `npm run pull` / `npm run status` がある。

## 実行

GAS エディタ（`npm run open`）で `createSurvey` を実行する。何度実行しても同じ結果になる。
誤操作を防ぐため、スプレッドシートのカスタムメニューは用意していない。

> **注意: アンケート実施中は実行しない。** フォームの項目を全て作り直すため、
> フォーム側では削除された設問への既存回答が失われ、「社内」「外部案件」タブの既存行は
> 新しいヘッダーと列がずれる。設問の変更は配布前に済ませ、実施中は GAS を触らない。

- **フォーム** は次の順で決まる
  1. このスプレッドシートに回答を送っている既存フォーム → 項目を全て作り直して更新
  2. スプレッドシートと同じ Drive フォルダにあるフォーム → 同様に更新
  3. どちらも無ければ新規作成し、同じフォルダへ配置
- **スプレッドシート** は紐づいているものをそのまま使う
  - 「社内」「外部案件」タブのヘッダー行を上書き（既存の回答行は保持）
  - 回答原本の「フォームの回答 N」シートは連携を張り直して作り直す。
    旧シートは回答が無ければ削除、あれば `（旧）` を付けて保持
- `onSubmit` トリガーは毎回作り直される（重複登録なし）

## 集計（「分析」「分析_明細」タブ）

GAS エディタで `buildAnalysis` を実行する。「分析」「分析_明細」タブを数式とグラフで組み立て直す。

- 集計はすべてスプレッドシートの数式（COUNTIF / COUNTIFS / FILTER など）で「社内」「外部案件」タブを
  直接参照する。**回答が増えると表もグラフも自動で更新される**ため、再実行が必要なのは
  設問や選択肢を変えたときだけ
- 前回アンケート（2026年4月・終了済み）は `PREV_SPREADSHEET_ID` の回答を非表示タブ「前回_2026-04」に
  値として写し、そこを参照する（初回実行時に前回スプレッドシートへのアクセス承認を求められる）
- 回答データには書き込まないので、アンケート実施中でも実行してよい
- 見た目（Arial 12pt、枠線は暗いグレー 1、割合は小数第一位、日付は yyyy年mm月dd日）は `constants.js` の定数で変えられる。
  「分析_明細」タブの枠線は実行時点の行数分だけ引くので、回答が大きく増えたら再実行して引き直す

「分析」タブ（A〜L 列に表、N 列以降にグラフ）:

1. 概要（回答数、前回の回答数、両回とも回答した人数、チーム別）
2. 主要指標の前回比較（速度向上・スキルアップ貢献・依存の不安・ジレンマ層・開発フロー・懸念 など）＋横棒グラフ
   - 前回は所属で分岐していないため、「前回(全体)」と「前回(社内チームのみ)」の両方を出す。今回の「社内」と比べるときは後者を基準にする
   - 速度変化は今回 1〜5 スケール、前回 はい/いいえ のため、今回は `SPEED_IMPROVED_MIN`（4）以上を「向上」として比較する
3. 選択肢分布の比較（利用歴・利用時間・役立ったフェーズ）＋グラフ
4. 今回のみの設問の集計（考え方の変化、時間の使い道、懸念、機能、期待するサポート、速度スコア分布）＋グラフ
5. クロス集計（利用時間 / 利用歴 / チーム × 効果・不安）
6. 外部案件の集計

「分析_明細」タブ（行数が回答に応じて伸びる一覧）:

1. 両回とも回答した人（メールアドレス一致）の回答の変化と、そのまとめ
2. 自由記述の一覧（困りごと、考え方が変わった理由、改善事例、他 LLM との比較、外部案件の要望）

列は設問タイトルの先頭（`constants.js` の `Q`）で特定するため、設問番号を変えたら `Q` も合わせる。

## フォームの内容

- Google ログインを必須にし、回答者のメールアドレスを自動収集する（記名式）
- 最初に「現在の主な所属」を選択し、社内PJ / 外部案件のセクションへ分岐
  - 社内PJ: チーム名 + 利用歴・利用時間・効果・考え方の変化・機能・要望など 19 問
  - 外部案件: 案件概要・AI利用ルール・利用ツール・効果・スキルアップ・要望など 9 問
- 社内セクション回答後は外部案件セクションを飛ばして送信
